# DengFOC-ODrive 单路板 硬件开发手册

适用板卡：灯哥 DengFOC-ODrive 单路驱动板（42 mm × 42 mm，主控 STM32F405RGT6）
适用固件：本仓库的 USB DFU 引导程序 + 自研 FOC 应用程序
版本：2026-10-20 初版

---

## 0. 可信度标记

本手册的引脚对应关系有四个来源，每一行都标注了来源：

| 标记 | 含义 |
|---|---|
| **【实测】** | 已经在这块板上用 SWD/USB/万用表确认过 |
| **【手册】** | 厂家《DengFOC ODrive 单路产品手册》明确写出 |
| **【ODrive】** | 由开源 ODrive v3.5 官方工程（fw-v0.5.1 `Board/v3`）推断 |
| **【待测】** | 目前没有依据或依据不足，使用前必须实测 |

**为什么可以用 ODrive v3.5 推断：** 这块板出厂时运行的是开源 ODrive 固件，USB 自报 `ODrive 3.5 Native Interface`、硬件版本 `3.5-24V`，厂家手册的配置流程（odrivetool、`axis0`、`abs_spi_cs_gpio_pin = 8` 等）也完全沿用 ODrive。如果接线和 ODrive v3.5 不一致，原厂固件就无法驱动电机，所以凡是原厂固件实际用到的功能，接线都应该和 ODrive v3.5 的 **M0 通道**一致。单路板只有一组三相输出，手册所有命令都作用于 `axis0`，即 M0。

## 2. MCU 与系统

### 2.1 芯片【实测】

| 项目 | 值 |
|---|---|
| 型号 | STM32F405RGT6（LQFP64） |
| 版本 | REV_ID 0x1007 |
| Flash | 1024 KB，单 Bank |
| SRAM | 112 KB + 16 KB（0x20000000 起共 128 KB）+ 64 KB CCM（0x10000000） |
| 读保护 | RDP Level 0（未加密） |
| 写保护 | 无 |
| 看门狗 | 软件启动（选项字节 WDG_SW = 1） |

### 2.2 时钟

| 项目 | 推荐值 | 来源 |
|---|---|---|
| HSE | 8 MHz 晶振（非有源，HSEBYP = 0） | 【实测】 |
| SYSCLK | 168 MHz（PLLM 8 / PLLN 336 / PLLP 2，或 ODrive 的 PLLM 4 / PLLN 168 / PLLP 2） | 【实测】【ODrive】 |
| USB 48 MHz | PLLQ = 7 | 【实测】 |
| APB1 / APB2 | 42 / 84 MHz（定时器时钟 84 / 168 MHz） | 【ODrive】 |
| Flash 等待周期 | 5 WS | — |

不要打开时钟安全系统（CSS）。芯片自带的 ROM 引导程序会打开 CSS，并在约 25 ms 后自行软件复位，所以这块板上 ROM USB DFU 不可用。原因尚未查明，应用程序里保持 CSS 关闭即可。【实测】

### 2.3 Flash 分区与引导程序【实测】

| 区域 | 地址 | 扇区 | 说明 |
|---|---|---|---|
| USB DFU 引导程序 | 0x08000000–0x08007FFF | 0–1（2 × 16 KB） | `firmware/bootloader/build/dfu_boot.bin`，USB 无法擦写 |
| 应用程序 | 0x08008000–0x080FFFFF | 2–11 | 自研固件放这里 |

进入 USB 烧录模式（电脑显示 `DengFOC DFU Bootloader`，VID:PID 0483:DF11）：

1. 应用区为空或无效时，上电自动进入；
2. 0.5 秒内连按两下 RESET；
3. 应用程序向 `0x2001FFF0` 写 `0xDF11B007`，再调用 `NVIC_SystemReset()`。

烧录命令：

```
STM32_Programmer_CLI -c port=USB1 -w app.bin 0x08008000 -v -s 0x08008000
```

### 2.4 调试接口【实测】

SWD 在 GPIO 排针上：DIO = PA13（SWDIO），CLK = PA14（SWCLK），G = GND。原厂固件没有关闭 SWD；自研固件也不要把 PA13/PA14 配成别的功能。

本机工具：Horco CMSIS-DAP（DAPLink）+ xPack OpenOCD（`interface/cmsis-dap.cfg`、`target/stm32f4x.cfg`）。STM32CubeProgrammer 不支持这个 DAPLink，但支持 USB DFU。

### 3.2 电流、电压、温度采样

| 信号 | MCU 引脚 | 脚号 | ADC 通道 | 来源 |
|---|---|---|---|---|
| B 相电流（M0_IB，DRV8303 放大器输出） | PC0 | 8 | ADC123_IN10 | 【ODrive】；【实测】低阻节点，DRV 未上电时约 150 mV |
| C 相电流（M0_IC，DRV8303 放大器输出） | PC1 | 9 | ADC123_IN11 | 【ODrive】；【实测】同上 |
| 母线电压 VBUS_S | PA6 | 22 | ADC12_IN6 | 【ODrive】；【实测】有分压网络，仅 USB 供电时读到 384 mV（×11 ≈ 4.2 V，USB 倒灌） |
| MOS 温度（M0_TEMP，NTC） | PC5 | 25 | ADC12_IN15 | 【实测】NTC 分压，室温读到 976 mV，按 ODrive 曲线为 32 °C |
| 刹车电路温度（AUX_TEMP） | PA5 | 21 | ADC12_IN5 | 【实测】也是 NTC 分压（969 mV），具体测的是哪个器件【待测】 |

A 相电流不采样，由 Ia = −(Ib + Ic) 算出。采样电阻在下桥（低侧）。【ODrive】

### 3.3 刹车电阻（AUX 端子，LM5109）

| 信号 | MCU 引脚 | 脚号 | 外设 / AF | 来源 |
|---|---|---|---|---|
| AUX_L（下管） | PB10 | 29 | TIM2_CH3（AF1） | 【ODrive】【手册】 |
| AUX_H（上管） | PB11 | 30 | TIM2_CH4（AF1） | 【ODrive】【手册】 |

**AUX_H 和 AUX_L 绝对不能同时为高**，否则耗散电路上下管直通，会烧 MOS（手册故障排查第一条就是这个）。

### 3.4 编码器

| 信号 | MCU 引脚 | 脚号 | 外设 / AF | 来源 |
|---|---|---|---|---|
| A（ENC_A / HALL_A） | PB4 | 56 | TIM3_CH1（AF2） | 【实测】被板载 AS5047P 的 A 输出驱动 |
| B（ENC_B / HALL_B） | PB5 | 57 | TIM3_CH2（AF2） | 【实测】被板载 AS5047P 的 B 输出驱动 |
| Z / I（ENC_Z / HALL_C） | PC9 | 40 | GPIO（EXTI9） | 【实测】被驱动为低（AS5047P 的 I 输出） |
| AS5047P 片选 CSn | PB3 | 55 | GPIO（ODrive GPIO8） | 【实测】读到 ERRFL = 0、DIAAGC = 0x09FF |
| AS5047P SCK / MISO / MOSI | PC10 / PC11 / PC12 | 51 / 52 / 53 | SPI3（与 DRV8303 共用） | 【实测】 |

- 板载 AS5047P 的 ABI 输出与外接 GH1.25 编码器口接在同一组 A/B/Z 上，手册要求二者不能同时接。【手册】
- AS5047P 的 ABI 模式 CPR = 4000（1000 线 × 4），SPI 模式 14 位（16384）。【手册】
- PB3、PB4 复位后默认是 JTAG 功能（JTDO / NJTRST，PB4 带上拉）。改成普通功能不影响 SWD。
- 外接 GH1.25 编码器口的针脚定义（几针、供电是 3.3 V 还是 5 V）手册没写。【待测】

### 3.7 FPC 8P 屏幕 / 串口接口（⑨）【待测】

手册称为"FPC 串口接口，可实现屏幕显示或无线控制"，没有给出针脚定义。单路板可用的串口候选：

- 与排针 Pin1/Pin2 共用 UART4（PA0/PA1）；
- USART6（PC6/PC7）：这两个脚在 ODrive 上是 M1 上桥 PWM，单路板没有 M1，可能被挪作他用。

在实测之前，不要驱动这两组引脚以外的 M1 引脚，也不要假设屏幕接口的定义。

### 3.8 单路板未使用的 ODrive M1 引脚

ODrive v3.5 的这些引脚给第二路电机用。单路板没有第二路功率级，它们可能悬空、接了测试点，或者被屏幕接口占用。【待测】在确认前，请保持为输入（或模拟输入），不要输出。

| ODrive 功能 | MCU 引脚 | 脚号 | 实测（2026-10-20，仅 USB 供电） |
|---|---|---|---|
| M1_AH / M1_BH / M1_CH（TIM8_CH1–3） | PC6 / PC7 / PC8 | 37 / 38 / 39 | 浮空 |
| M1_AL / M1_BL / M1_CL（TIM8_CH1N–3N） | PA7 / PB0 / PB1 | 23 / 26 / 27 | 浮空 |
| M1_nCS | PC14 | 3 | 浮空 |
| M1_IB / M1_IC | PC3 / PC2 | 11 / 10 | 低阻节点，约 165 mV，用途未知 |
| M1_TEMP | PA4 | 20 | NTC 状分压，约 970 mV |
| M1_ENC_A / M1_ENC_B / M1_ENC_Z | PB6 / PB7 / PC15 | 58 / 59 / 4 | 浮空 |

"浮空"表示内部上拉、下拉都能把它拉过去，说明没有接东西，或者只接了高阻器件（例如未插屏幕的 FPC 座）。

## 5. 外设分配（参考 ODrive v3.5，可按需调整）

| 外设 | 用途 | ODrive 配置 |
|---|---|---|
| TIM1 | M0 三相 6 路 PWM | 中心对齐模式 3，ARR = 3500（168 MHz → **24 kHz**），PWM2 模式，死区 20 个时钟（≈119 ns），RCR = 2，TRGO = Update |
| TIM2 | 刹车电阻 PWM（CH3 = AUX_L，CH4 = AUX_H） | 中心对齐，ARR = 4096（84 MHz → ≈10 kHz），CH3 极性低 |
| TIM3 | M0 编码器（A/B） | 编码器模式 TI12，输入滤波 4 |
| TIM5 | 排针 Pin3/Pin4 PWM 输入捕获 | CH3/CH4 双边沿，滤波 15 |
| ADC2 / ADC3 | B / C 相电流注入通道 | 由 TIM1_TRGO 触发，3 周期采样 |
| ADC1 | 母线电压、温度等慢速量 | ODrive 运行时用 DMA 连续扫描所有通道 |
| SPI3 | DRV8303 + AS5047P | 主机、模式 1（CPOL 0 / CPHA 1）、16 位、MSB 先行、/16（2.625 Mbit/s） |
| UART4 | 排针 Pin1/Pin2 | 115200，DMA1 Stream2（RX）/ Stream4（TX） |
| CAN1 | CAN 总线 | 预分频 7，BS1 6 TQ，BS2 5 TQ → 500 kbit/s |
| USB OTG FS | 设备模式 | 不开 VBUS 检测 |

ODrive 的电流采样时序：RCR = 2 时，TIM1 的更新事件交替出现在计数器顶点和底点（16 kHz）。在底点，下桥导通，低侧采样电阻上有相电流，这时采相电流；在顶点采零点偏置。电流环 8 kHz。

## 6. 换算公式

### 6.1 相电流

```
V_adc  = adc / 4096 × 3.3
I_phase = (V_adc − 1.65) / G / R_shunt
```

- DRV8303 放大器的参考电压是 AVCC/2 ≈ 1.65 V。
- 增益 G 通过 SPI 设置为 10 / 20 / 40 / 80 V/V。
- R_shunt：ODrive v3.5 是 **0.5 mΩ**。【ODrive】本板的采样电阻值【待测】，请看板上丝印（例如 `R0005`）。
- 电流方向的符号要结合实测确认。

参考量程（0.5 mΩ）：G = 80 时约 ±41 A，G = 40 时约 ±82 A，G = 20 时约 ±165 A。本板持续 30 A、峰值 50 A，一般用 G = 40 或 80。

### 6.2 母线电压

```
V_bus = adc / 4096 × 3.3 × 11
```

24 V 版本的分压比是 11（满量程约 36.3 V）。【ODrive】原厂固件自报 `3.5-24V`，所以按 11 计算。

### 6.3 MOS 温度

ODrive v3.5 的 NTC 多项式，x = V_adc / 3.3：

```
T(°C) = 363.94·x³ − 462.15·x² + 307.55·x − 27.73
```

本板 NTC 型号未知，这个公式只能作参考，要用热风枪或室温对比校准。【待测】

## 7. DRV8303 使用要点

- SPI 时序：16 位、模式 1，nSCS 低有效，最高 10 MHz。寄存器：0x00 Status1、0x01 Status2、0x02 Control1、0x03 Control2。
- EN_GATE 拉高后，DRV8303 才会启动内部稳压（GVDD 约 11 V、AVDD 约 6 V、DVDD 约 3.3 V），SPI 才能通信。DRV8303 由主电源 PVDD 供电，**只插 USB 时它不工作**。【手册】故障排查第四条
- 上电顺序：主电源已接 → EN_GATE 拉高 → 等待约 10 ms → 写 Control1/Control2（栅极电流、过流阈值 OC_ADJ、电流放大增益、6 路 PWM 模式）→ 回读确认 → 读 Status 清故障 → 才允许输出 PWM。
- 零点校准：可以用 Control2 的 DC_CAL 位短接放大器输入，在 PWM 关闭时采 ADC 偏置。
- nFAULT 拉低表示过流、欠压或过温，应立即关闭 PWM 并读 Status 寄存器。

## 8. 安全规范（必读）

1. **程序一启动，先把功率级引脚设到安全状态**：
   - PB12（EN_GATE）→ 推挽输出，低；
   - PB10/PB11（AUX_L/AUX_H）→ 推挽输出，低；
   - TIM1 的 MOE 保持 0，等 DRV8303 配置完成、电流零点校准完成后再打开。
2. AUX_H 与 AUX_L 永远不能同时为高。
3. 改动功率级相关代码后，第一次上电用限流电源，电流限制在 1–2 A，不接电机或接小电机。
4. 刷写和调试时，只要不需要驱动电机，就保持主电源（XT30）断开，只接 USB。
5. 本节第 1 条所列以外、尚未确认的引脚（标注【待测】的），保持为输入，不要输出。

## 10. 外接编码器的接法

板载 AS5047P 的 A/B/I 输出一直在驱动 PB4/PB5/PC9。外接 GH1.25 编码器口也接在这三根线上，所以**焊了 AS5047P 的板子不能再用外接编码器口**（手册也这么要求）。SPI3 没有引到任何接口。外接编码器可以选：

| 方案 | 接线 | 说明 |
|---|---|---|
| ABZ 增量编码器，用排针 | A → Pin1（PA0），B → Pin2（PA1），Z → Pin3/Pin5 | TIM2 或 TIM5（32 位）的编码器模式只能用 CH1/CH2，PA0/PA1 正好是。代价是占用 UART4 |
| PWM 输出的磁编码器（如 MT6701、AS5048A 的 PWM 输出） | 信号 → Pin3（PA2）或 Pin4（PA3） | TIM5_CH3/CH4 输入捕获，接线最少，延迟较大 |
| SPI 磁编码器（如 MT6701、AS5048A、MA730） | 用排针 Pin3–Pin7 做软件 SPI | 16 位读取约 10 µs，能满足 8–16 kHz 电流环 |
| I²C 磁编码器（如 AS5600） | 用排针两脚做软件 I²C | 读取慢，只适合低速场景 |
| 继续用板载 AS5047P | 磁铁对准板子背面芯片，间距 1–3 mm | SPI3 已实测可用，14 位精度最高 |

排针 Pin 号和 MCU 引脚的对应要先用 `watch` 命令确认（见第 11 节）。

## 11. 自检程序（firmware/apps/selftest）

自检程序链接在 0x08008000，通过 USB DFU 烧录。运行后出现 USB 虚拟串口（0483:5740，"DengFOC SelfTest"）。

```
cd firmware/apps/selftest
bash build.sh
STM32_Programmer_CLI -c port=USB1 -w build/selftest.bin 0x08008000 -v -s 0x08008000
python ../../../tools/dengfoc_cli.py info adc enc pull
```

| 命令 | 作用 |
|---|---|
| `info` | 芯片 ID、UID、VDDA、主频、复位原因 |
| `adc` | 所有可做 ADC 的引脚的电压 |
| `pull` | 对每个非功率引脚分别开上拉和下拉读电平，判断有没有接东西 |
| `watch` | 30 秒内实时报告排针 Pin1–Pin7 的电平变化（引脚已开下拉，用串 1 kΩ 的导线把某个 Pin 碰到"3"） |
| `enc` | 读板载 AS5047P |
| `drv` | 读 DRV8303 寄存器。只有主电源电压大于 9 V 时才执行，期间所有栅极输入保持低电平 |
| `dfu` | 回到 USB 烧录模式（以后烧录新程序不用再双击 RESET） |

安全设计：上电第一步就把 EN_GATE、AUX_H/AUX_L、六路栅极输入全部设为低电平输出，整个程序运行期间都不会打开功率管。
